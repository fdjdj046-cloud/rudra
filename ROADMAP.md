# Дорожная карта

Источник требований — `REQUIREMENTS-2.0.md` (локальная копия у сопровождающего). Тег `v2.0.0` означает **Server**. Профиль Desktop ведётся в ветках `desktop-3.x` и в эту карту как работа `main` не входит. Общие куски (память, SMP, VFS, сеть, динамический линкер) делаются на `main`, потому что без них не соберётся и сервер.

Критический путь: **SMP → VFS, page cache, ext4 → динамический линкер и сигналы → сеть → init и пакеты → самосборка**.

Пункты 0.1–0.9 записаны в `doc/`: [compat-contract](doc/compat-contract.md), [profiles](doc/profiles.md), [architecture](doc/architecture.md), [unsafe](doc/unsafe.md), [governance](doc/governance.md). aarch64 (0.10) и HCL (0.11) в 2.0.0 не обязательны и не начаты.

Долг 1.1: у каждого поднятого CPU свой TSS и тик LAPIC. `sched_setaffinity` запоминает младший бит маски, и задача с кадром из ring 3 исполняется на этом CPU. Кадр, застигнутый в ядре, остаётся на своём CPU до возврата в ring 3. x2APIC есть: INIT-SIPI-SIPI идёт по xAPIC (INIT IPI в x2 не поддерживается), затем каждый CPU переключается на MSR-интерфейс; режим читается из IA32_APIC_BASE, а не из разделяемого флага. Живой прогон: `-cpu qemu64,+x2apic -smp 2` — оба CPU в x2, IPI и балансировка на месте. Пока `sys_clone` и разбор адресного пространства держат IF выключенным, тик LAPIC на этом CPU не приходит и квант сдвигается. `nanosleep` и `CLOCK_MONOTONIC` на TSC. `CLOCK_REALTIME` — CMOS RTC, без NTP. `FUTEX_CMP_REQUEUE` есть (glibc `pthread_cond_broadcast` будит одного и переставляет остальных на второй адрес; переставленные спят до явного WAKE). Есть и REQUEUE без сравнения (op 3). PI нет. `rseq` обрывает критическую секцию и на входе в syscall (rip → abort handler, Linux-семантика). Перебалансировка есть: свободная задача (без явного `sched_setaffinity`) рождается на наименее загруженном CPU, а простаивающий CPU ворует чужие свободные (не привязанные, не исполняющиеся) задачи. Живой прогон: 4 потока `threads.elf` на `-smp 2` садятся на оба CPU (`threads on cpus: 1 0 1 0`).

Долг 1.2: кэш ARP — восемь записей, девятая вытесняет самую старую. `SO_REUSEADDR` и `SO_BROADCAST` принимаются и не запоминаются. Датаграмма UDP не длиннее 1280 байт. При загрузке с картой DHCP запрашивается сразу; без сети загрузка не страдает. `SOCK_STREAM` — это TCP (петля и провод). Сумма 0 у входящего UDP на IPv4 не проверяется.

Долг 1.3: перехваченный сигнал с `SA_RESTORER` доставляется, когда тик возвращается в ring 3, и на возврате из syscall. Смертельный сигнал и `SIGKILL` забираются без syscall: планировщик убивает задачу с pending-fatal до выбора, `deliver_timer` прибивает входящую (iret случится ещё раз, но не дольше кванта). `nanosleep`, `clock_nanosleep`, `futex WAIT`, блокирующие pipe, poll, select, `epoll_wait`, `recvfrom` и `wait4` (если зомби ещё нет) возвращают `EINTR`. Остаток сна пишется в `rem`. `SA_RESTART` есть у перехваченных обработчиков: pipe/poll/select/epoll/recvfrom/wait4/futex продолжают ждать вместо EINTR; сон — нет (как в Linux). Чтение консоли сигнал не прерывает. `SIGCHLD` ставится родителю при exit процесса; поток `CLONE_VM` его не шлёт. Без обработчика `SIGCHLD` игнорируется и wait не будит. Чужой tid получает бит и входит в обработчик на своём тике или syscall. `SIGSTOP` и сигналы остановки сбрасываются. Очередь rt-сигналов 34–64 есть (глубина 8 на задачу, при переполнении — тихий сброс; `sigqueue` принимает, значение не хранит). `PT_INTERP` — один уровень: вложенный интерпретатор отвергается, `ET_DYN` принимает `R_X86_64_RELATIVE` и символьные `R_X86_64_64`/`GLOB_DAT`/`JUMP_SLOT` (поиск в `.dynsym` своего объекта, по имени для `SHN_UNDEF`). Интерпретатор `ET_EXEC` садится на свой адрес, `ET_DYN` — на `0x800000`. Смерть по умолчанию — `exit(128+sig)`, не `WIFSIGNALED`. Без `SA_RESTORER` перехваченный сигнал не доставляется: для смертельных по умолчанию это `exit`. epoll следит за номером fd, не за описанием файла: `close` этого номера снимает интерес, даже если остался `dup`. `EPOLLET` — настоящий edge-триггер (фронт по снимку готовности, сброс на ADD/MOD). `epoll_pwait` ставит временную маску сигналов. poll и select по самому epoll-fd ничего не видят. Таймаут длиннее 60 с — `EINVAL`. Наборов не больше 16, интересов не больше 32. `/proc/meminfo` — usable из карты и свободные кадры, не MemAvailable. `/proc/stat` кладёт тики планировщика в поле system, user и idle не разделяет. `/proc/self/status` показывает имя, pid, ppid, uid/gid (fsuid равен euid) и seccomp текущей задачи; без задачи это `kernel` и нули. Каталог `/proc/<pid>` есть у каждой задачи в таблице, включая зомби: `status` и `cmdline` (путь exec и NUL, не полный argv). Чужого pid нет. `/sys` — два файла и каталоги до них, не sysfs.

Долг 1.4: кэш чтения — 16 слотов. Кусок попадает в него, только если это ровно 4096 байт и LBA кратен 8. Запись пересекающегося диапазона слот выкидывает и не подменяет данные устройства, поэтому проверка записи ext2 читает диск. Page cache, ext4, NVMe и AHCI нет.

Долг 1.5: uid/euid/suid и gid при старте 0. `setuid`/`setgid` у root пишут все три id, иначе только effective и только на один из уже имеющихся. Чужой id — `EPERM`. `execve` id не сбрасывает, `clone` копирует. Дополнительных групп, входа и пакетов нет. Создание (`open` с `O_CREAT`, `mkdir`) штампует владельца: euid/egid задачи пишутся в inode (uid lo@2/hi@120, gid lo@24/hi@122); `stat`/`statx`/`fstat` читают inode. У RFS2 и синтетики владельца по-прежнему нет — там root (0,0). Проверки доступа по владельцу нет. `AT_UID` и соседи берутся из учётных данных задачи на `exec`/`spawn`. PID1 — `/bin/init.elf`: не читает консоль, через `fork`+`execve` поднимает `/bin/shell.elf` и крутит `wait4`. Если init нет, PID1 остаётся шелл. Exit отдаёт детей PID1 по tid (поиск по `Runnable` снят: init может спать в `wait4` на своём CPU, когда сирота рождается на AP), и, если среди них уже есть зомби, ставит PID1 `SIGCHLD`. Смерть PID1 — паника ядра: репарентить и reap'ать больше некому.. `getppid` задачи без родителя возвращает 0, не 1. `CLONE_FS` делит один cwd и umask, обычный fork копирует оба. `execve` каталог и umask не сбрасывает. umask срезает биты режима у `mkdir` и у файла, которого ещё не было. `chmod` и `fchmod` пишут биты 07777 и не меняют тип. `stat` и `statx` читают записанный режим. Проверки доступа по этим битам нет.

Долг 1.7: strict включается через `prctl(PR_SET_SECCOMP, 1)` или `seccomp(SET_MODE_STRICT)`. Фильтр (op 1) — `ENOSYS`, режим 2 у prctl — `EINVAL`. Повторно выключить нельзя: после включения prctl уже запрещён, а если сеттер всё же вызван — `EINVAL`. Разрешены номера 0, 1, 15 и 60. `exit_group` убивает. Нарушение — `exit(128+SIGKILL)`, не постановка в очередь сигналов. `clone` копирует режим, `execve` его сохраняет. Namespaces, cgroups и capabilities нет.

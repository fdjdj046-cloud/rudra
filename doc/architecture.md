# Архитектура ядра

## Модель

Монолит. Драйверы, VFS и сеть живут в ядре, в одном адресном пространстве. Микроядро и вынос драйверов в userspace не выбираем: на одном ядре гонять сообщения ради virtio дороже, чем писать драйвер рядом с блочным слоем.

Пользовательские службы (сеть, диски, контейнеры) ходят только через Linux ABI. Внутри ядра своего стабильного RPC нет.

## Драйверы

Свои, на Rust, против шин, которые есть в ядре (PCI, потом virtio, NVMe, USB xHCI).

Чужой драйвер Linux не подключается ни как модуль, ни через shim. Порт означает переписать устройство на наши типы, а не собрать `.ko`. Проприетарные прошивки в git не кладём. Когда появится загрузка `/lib/firmware`, блоб остаётся файлом пользователя, с отдельной лицензией, и в образ по умолчанию не входит.

Порядок для сервера: virtio-blk (есть) → virtio-net → NVMe и AHCI → e1000e и серверные NIC из требования 5.6. GPU, звук и Wi-Fi в этот порядок не входят.

## Архитектура CPU

Цель — **x86-64-v2** (SSE3, SSSE3, SSE4.2, POPCNT, CMPXCHG16B). aarch64 в 2.0.0 нет.

Флаг `-C target-cpu=x86-64-v2` пока не включён. Стандартный `qemu64` не обязан иметь SSE4.2, и ядро, собранное под v2, перестанет грузиться в текущих `test.sh` и `smoke.py`. Сначала командные строки QEMU получат CPU уровня v2, потом включится флаг. До этого компилятор остаётся на базовом x86-64.

# Compat Contract

Ориентир ABI — **Linux x86_64, стабильные номера syscall'ов Linux 6.1 LTS**. Берём номера, раскладку аргументов (`rdi`, `rsi`, `rdx`, `r10`, `r8`, `r9`) и смысл вызова. Код ядра Linux не копируем.

Это контракт профиля **Server** на пути к тегу `v2.0.0`. Пока тега нет, обещание для пользователя — только [RELEASE_NOTES.md](../RELEASE_NOTES.md) версии 1.0.1. Всё ниже про 2.0 — цель, не текущий образ.

## Что обещано к тегу 2.0.0 (Server)

- Реализованный syscall либо работает по семантике Linux 6.1, либо возвращает `ENOSYS`. «Почти работает» в таблицу совместимости пишется как **частично** и в Known Issues.
- Номера, которые уже отдали, не переезжают и не меняют смысл. Свои вызовы — только диапазон `1000…1999` (сейчас занят `1000`, дамп задач).
- Динамические бинарники glibc и musl, `/proc`, `/sys`, сокеты, сеть и контейнерный минимум из раздела 8 требований. Список закрытых номеров публикуется таблицей «реализовано / частично / ENOSYS».
- `lseek` возвращает позицию, `pwrite` пишет по offset, `link` создаёт жёсткую ссылку, `munmap` отдаёт память, `futex WAKE` будит. Пока это не так, тег 2.0.0 не ставится.

## Что не обещано

- Совпадение с ядром новее 6.1: новые номера могут остаться `ENOSYS` до следующего контракта.
- Покрытие 100 % таблицы Linux, полный eBPF, SELinux, i386-compat, Wine/Proton.
- Профиль Desktop. Он вынесен в ветки `desktop-3.x`, см. [profiles.md](profiles.md).
- Внутренние структуры ядра, формат модулей, номера своих syscall'ов выше 1999.

## Сейчас (дерево после 1.0.1, ещё не 2.0)

Около шестидесяти номеров. Часть из них урезана: `lseek` возвращает 0, `pwrite` игнорирует позицию, `link` копирует байты, `munmap` ничего не отдаёт, `getrandom` — не CSPRNG, сигналы 1–31 доставляются только на возврате из syscall и только с `SA_RESTORER`, динамического линкера нет. Это честный 1.x, не предварительный 2.0.
